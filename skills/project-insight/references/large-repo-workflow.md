# 大型仓库并行解读工作流

> 仅当**解读规模门控**触发时使用：`source_repo` 有效代码行（剔除测试/构建/生成/示例代码后）估算 **超过 5 万行**。
> 中小项目走 SKILL.md 的单 agent 流程；这里的所有产物**同样必须满足真源验证铁律**，不允许因并行而降级。

## 门控与模式选择

1. 估算有效代码行：`find` + `wc -l` 或 `cloc`，按顶层目录分组；剔除测试、构建/部署配置、生成代码（protobuf、lock 文件）、示例/文档。
2. 超过阈值 → 询问用户选择解读深度：

| 模式 | 核心模块覆盖率 | 次要模块覆盖率 | 适用 |
|------|----------------|----------------|------|
| 快速 | ≥ 30% | ≥ 10% | 快速掌握全貌 |
| 标准（默认） | ≥ 60% | ≥ 30% | 常规架构解读 |
| 深度 | ≥ 90% | ≥ 60% | 研究每个设计决策 |

覆盖率 = 通过 Read 实际读过的行范围并集 / 文件总行数。只读了 <30% 的文件记为"未读"；大文件（>500 行）分段读，覆盖类型定义/核心逻辑/测试。

## 模块划分与并行

- 按**业务功能**划分模块，不按目录/文件；一个逻辑模块可跨文件，一个文件也可属多模块。识别为核心模块（创新点、架构关键）与次要模块（工具、封装）。
- **每个核心模块 → 一个并行 subagent**；所有次要模块 → 合并为一个 subagent 批量处理。并行启动，各自只分析分配的文件。
- 主 agent 等待期间不读 subagent 负责的源码，转去做：读项目架构/设计文档、外部调研、设计解读骨架。

## 主 agent 分工

1. 先确立**根因**、整体设计哲学，写入解读开头锚点。
2. 设计**叙事线**（参考 analysis-guide.md）：核心模块按"读者理解最佳路径"排序，写明模块间过渡逻辑。
3. 派发 subagent，prompt 注入：项目定位 / 整体架构 / 设计哲学 / 该模块在系统中的位置 / 叙事上下文 / 覆盖率要求。
4. 并行分析完成后，主 agent 做**交叉验证**：
   - **覆盖率门控**：读每个模块草稿末尾的覆盖率表，未达标模块补读或向用户说明原因。
   - **抽查验证**：从每个核心模块选 2-3 个关键论断，回到源码逐行核实（含 `文件:行号` 重定位）。
   - **全局关联**：核对每个模块分析是否连回整体设计哲学。
   - **跨模块复核**：subagent 标注的 `【待主 agent 验证】` 结论集中核对。

## Subagent Prompt 模板

```
你是一位资深架构师，对 {项目名} 的「{模块名}」模块做深度解读。
## 背景
- 项目定位: {一句话}
- 整体架构: {简述}
- 设计哲学: {贯穿项目核心理念}
- 该模块在系统中位置: {与其他模块关系}
- 叙事上下文: {前一个模块讲了什么、读者带着什么疑问进入本模块、本模块为下一个模块铺垫什么}
## 需要分析的文件
{文件路径列表}
## 分析结构
1. 在项目中的角色（去掉它系统会怎样）
2. 解决什么问题、根因
3. 设计思路（方案、放弃的替代方案、核心模式）
4. 关键数据结构（只贴理解必需的类型/接口）
5. 核心流程 —— Mermaid/文字 + 标注 {仓库相对路径:行号}
6. 与其他模块的协同（依赖、协作、共享状态；跨模块结论标【待主 agent 验证】）
7. 关键设计决策 1-3 个：权衡与替代方案代价
8. 亮点与问题
## 硬性要求
- 深度遵循 references/analysis-guide.md（Why>What、权衡、全局关联、叙事衔接）。
- 每个 {路径:行号} 引用，snippet 必须从本次实际读取内容**逐字复制**，写出后可让主 agent 用真源重定位。
- 覆盖率：当前模式 {模式}，目标 {百分比}%。草稿末尾附覆盖率明细表（文件名|总行数|已读行数|覆盖率%|未读原因），末行合计标达标✅/❌；未达标继续读到位。
- 大模块（>5000 行）增量写入，先 Write 后 Edit 追加，单次 ≤300 行。
## 输出
写入 {work_dir}/drafts/06-module-{模块名}.md
```

> 关键差异点：与普通 subagent 流程不同，这里的 subagent 产出是**解读草稿**，主 agent 必须负责把每个引用重定位到真实行号、合并叙事、剔除跳转指示，最终按 SKILL.md 的落地规范写进 `kb_repo`。

## 文档落地

并行解读的最终产物仍是 `{kb_repo}/{分类}/{项目}/README.md`（可拆 `01-*.md` 分层 + 索引同步 + 真源校验），与单 agent 流程产出格式完全一致。subagent 草稿只是中间态，不进 `kb_repo`。

## 边界

- 真源验证、kb_repo 判定、索引同步、只落盘不 git commit —— 一律沿用 SKILL.md 规定，不因并行改变。
- 若解读仍用 RAG（超大仓库），切分时给每个 chunk 记录真实起始/结束行，保证可重定位。
