# 方案类型裁剪清单（types）

类型**不改变档位**（档位由复杂度定，见 SKILL.md），只决定三件事：

1. **重心**：模板里哪些章节要加深、写得具体；
2. **特有要点**：该类型必须覆盖、通用模板没列的内容；
3. **可裁剪**：与本类型无关、可以删或一句话带过的章节。

冲突时以类型清单为准，并在文档「范围与边界」或相应章节说明取舍理由。

## 类型判定速查

| 类型 | 命中信号（用户表述举例） |
|------|--------------------------|
| 架构设计 | 系统架构、微服务拆分、模块化、平台化、跨系统集成、重构 |
| API 设计 | 接口/API/OpenAPI、REST/RPC/gRPC、对接第三方、协议 |
| 数据模型设计 | 数据库设计、ER 图、表结构、分库分表、索引、存储选型 |
| 性能优化 | 高并发、QPS/RT 不达标、瓶颈、缓存、限流、压测 |
| 安全方案 | 认证授权、登录态、数据加密、防爬/防刷、合规 |
| 通用（默认） | 未命中以上任一，或复合需求但无明显侧重 |

## 通用（默认）

按 `templates.md` 原样展开，不加不减。

## 架构设计

- **重心**：总体架构设计——设计原则、架构图、系统边界与职责、核心流程、数据流转。
- **特有要点**：
  - 架构图（Mermaid 规范见 `quality-bar.md`）；职责用「模块/服务 × 职责」表列清，避免职责重叠。
  - 单点与故障域分析：哪些组件是单点、如何降级/容错。
  - 演进路径：当前方案与现状的差距、分期落地的切分点。
- **可裁剪**：详细接口定义、表结构 DDL——可引用其它文档，不必在本文重复。
- **联动**：用户要独立 SVG 架构图交付物 → 改用/联动 `svg-maker`。

## API 设计

- **重心**：接口设计、数据模型、交互时序。
- **特有要点**：
  - 接口定义：方法/路径/请求响应示例（可用代码块，原则见 `quality-bar.md`）、错误码约定、鉴权方式、幂等与限流（如涉及）、**版本与兼容策略**。
  - 时序图表达关键调用链（sequenceDiagram）。
  - 列出「不做什么」：明确不在本次范围开放的接口能力，防止接口膨胀。
- **可裁剪**：成本分析、压测方案等与企业级无关章节。

## 数据模型设计

- **重心**：数据模型、存储设计。
- **特有要点**：
  - ER 图（erDiagram，实体名英文驼峰、关系标注中文）、实体与字段说明、索引设计、读写比例假设。
  - 一致性取舍：强一致/最终一致、事务边界；分库分表/分区只在该需求明确时展开，并给路由键与迁移方案。
- **可裁剪**：消息与异步、可观测性等无关章节（轻量/标准档）。
- **补充**：若文档里给了表结构或索引，标准/完整档应在评审清单里核一遍索引与查询匹配（见 `quality-bar.md`）。

## 性能优化

- **重心**：瓶颈分析、优化方案对比与取舍。
- **特有要点**：
  - 先给**现状基线**与目标指标：QPS、RT（P99）、资源水位——没有量化就不写优化。
  - 瓶颈假设要可验证：给出验证手段（压测/采样/AB），方案给「预期收益 + 代价 + 回退」。
- **可裁剪**：与性能无关的企业级章节；完整档才展开容量规划与压测方案，轻量/标准档给验证步骤即可。

## 安全方案

- **重心**：威胁建模、防护措施、审计与合规点。
- **特有要点**：
  - 资产与信任边界（谁可信、什么数据敏感）、主要威胁清单与对应防护、认证授权与数据加密、审计/合规要求。
- **可裁剪**：性能压测、成本分析等无关章节。

## 两轴组合示例

| 用户需求 | 档位 | 类型 | 落点 |
|----------|------|------|------|
| 「给订单服务加一层本地缓存，缓解 DB 压力」 | 轻量 | 性能优化 | 基线 + 缓存方案取舍 + 验证步骤 |
| 「设计一个 API 网关子系统」 | 标准 | 架构设计 + API 设计 | 标准档骨架 + 网关职责表 + 接口与鉴权 |
| 「核心交易系统整体重构为微服务」 | 完整 | 架构设计 | 完整档骨架 + 演进路径 + 故障域 + ADR |
