# slim 分支：瘦身当前仓库为浅克隆

本分支核心为独立脚本 `scripts/git-slim.sh`（单一真源，与 `/git/slim` 命令共用）。运行它即可完成全部流程（计时+失败捕获+9 步+耗时汇总）。

## 运行方式

运行脚本 `scripts/git-slim.sh [天数]`：

- 无参数 → 默认保留最近 30 天历史
- 传数字 `N` → 保留最近 `N` 天历史。**`N` 同时联动两个保留范围**：浅克隆保留的提交深度、以及旧 tag 的清理 cutoff。若只想进一步压缩磁盘，可传更小天数（如 `7`、`1`）。

> 本流程的动机主要是**释放磁盘占用**：旧 tag 与远端跟踪引用勾住的历史（含提交进 git 的大二进制文件）占了磁盘，脚本清理后配合 gc 将它们物理删除。

**最高优先级：绝不丢失任何本地未提交改动。** 脚本含自提交安全校验：若仓库存在作者/提交者为当前 git 用户本人的提交，会直接报错中止，以保护本人工作历史。

## 背景：为什么默认要清理引用与旧 tag

本流程面向**只分析、永不提交**的仓库（本 skill 约定的使用场景）。仅做 `--shallow-since` 浅拉取往往无法真正瘦身：仓库里**数百个远端跟踪分支引用**与**旧的 release tag** 一旦存在，就会各自把完整历史（含提交进 git 的大二进制文件）重新"勾住"，抵消浅克隆效果。

因此脚本额外做两步清理（对只读仓库是安全的，需要时 `git fetch` / `git fetch --tags` 即可恢复）：

- **清理远端跟踪引用**：仅保留 `origin/<当前分支>` 与 `origin/HEAD`，删除其余 `refs/remotes/origin/*`（含 `packed-refs` 中的条目）。
- **清理旧 tag**：删除**创建时间早于保留深度 `N` 天**的 tag（判定标准：按创建时间，用 unix 时间戳比较，避免字符串时间格式的坑）。

## 脚本内部执行流程（供参考/排障）

1. 注入计时与失败捕获机制（`run()`/`trap`）
2. 前置安全校验（自提交检测）：发现本人提交即中止
3. 记录瘦身前体积（`du` 写入临时文件供步骤 9 对比）
4. 安全检查并缓存改动（`git stash push -u` 备份本地改动）
5. 解析保留深度（默认 `30 days ago`；`N` 天联动到 tag 清理的 cutoff）
6. 浅拉取：`git fetch --shallow-since=<深度> --prune origin <当前分支>`
7. 本地分支对齐远端（`git merge --ff-only`，失败则 `git reset --soft`）
8. **清理远端跟踪引用**（仅留 `origin/<当前分支>` 与 `origin/HEAD`）
9. **清理 `N` 天前创建的旧 tag**
10. 收缩 reflog 并 gc（**顺序必须在清理引用/tag 之后**、用非 aggressive：`git reflog expire --expire=now --all` + `git gc --prune=now`）
11. 恢复本地改动（`git stash pop`）
12. 核对工作区 + 核对 `HEAD == origin/<当前分支>`（只对齐，**不跑 `git pull`**）
13. **输出磁盘收益对比**：`.git` 目录大小前→后 + 释放磁盘量（KiB/MiB）+ 耗时汇总

> **防超时关键**：不要用 `git gc --aggressive`，也务必先清理引用与 tag 再 gc。若在数万对象、数 GB 待删内容时先跑 aggressive，会耗时几十分钟甚至超时（实战教训）。

## 验收标准

- `.git` 体积明显缩小；本地改动完整保留；`HEAD` 与 `origin/<当前分支>` 对齐
- 输出体现**释放磁盘量**与前/后体积对比，以及各步骤耗时汇总，便于定位耗时瓶颈

## 警示（可向用户提示）

- **磁盘占用与本流程关系**：释放的是 `.git` 中由旧 tag/远端引用勾住的无主对象。删除后磁盘占用下降；需要恢复完整内容时空间会回涨。
- 30 天（或 `N` 天）以前的提交、远端分支跟踪引用、旧 tag 将本地不可见；需要时可恢复：
  - 完整历史：`git fetch --unshallow`
  - 远端分支引用：`git fetch origin`
  - 旧 tag：`git fetch --tags origin`
  （恢复都会令空间回涨）
- 清理旧引用/tag 仅对"永不提交"的只读分析仓库安全；若会向远端推送，请谨慎并事先确认
