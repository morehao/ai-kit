# 方案专题（focus-areas）

专题是**可多选的加固方向**，不是文档分类标签。它决定三件事：

1. **重心**：骨架里哪几节要写深、写细；
2. **必答项**：该方向绕不过去、评审一定会问的问题；
3. **可裁剪**：与本方案无关、可以删掉的章节。

专题**不改变档位**（篇幅与评审范围由 `templates.md` 的档位决定）。多个专题叠加时，同一章节取并集加深；专题必答项与模板骨架冲突时以专题为准，并在文档中说明取舍理由。

## 专题判定速查

| 专题 | 命中信号（用户表述举例） |
|------|--------------------------|
| 架构设计 | 系统架构、微服务拆分、模块化、平台化、跨系统集成 |
| API 设计 | 接口/API/OpenAPI、REST/RPC/gRPC、对接第三方、协议、对外开放 |
| 数据模型设计 | 数据库设计、表结构、ER 图、索引、分库分表、存储选型 |
| 性能与容量 | 高并发、QPS/RT 不达标、瓶颈、缓存、限流、压测、容量规划 |
| 安全 | 认证授权、登录态、数据加密、防爬防刷、权限模型、合规 |
| 迁移与重构 | 重构、拆分、替换、数据迁移、切流、灰度、下线旧系统 |
| （无专题） | 未命中以上任一，或多方向但无明显侧重 → 按模板原样展开 |

## 架构设计

- **重心**：总体架构——设计原则、架构图、系统边界与职责、核心流程、数据流转。
- **必答项**：
  - 「模块/服务 × 职责」表：职责不重叠、不遗漏，并标明**数据所有权**归属（谁能写、谁只能读）。
  - 单点与故障域：哪些组件挂了会整体不可用，如何降级/容错；可用性按 `quantification.md` 做串联预算。
  - 调用链深度：跨服务调用次数、超时与重试策略（重试必须配退避 + 幂等，否则放大故障）。
  - 演进路径：与现状的差距、分期切分点，每期可独立上线、可独立回退。
- **可裁剪**：详细接口定义、表结构 DDL——可引用其它文档，不在本文重复。
- **联动**：用户要独立 SVG 架构图交付物 → 改用/联动 `svg-maker`。

## API 设计

- **重心**：接口定义、交互时序、错误与兼容。
- **必答项**：
  - 接口清单：方法/路径/请求响应示例、错误码约定、鉴权方式（示例原则见 `quality-bar.md`）。
  - 幂等与重试语义：哪些接口可安全重试，幂等键怎么传。
  - 版本与兼容策略：破坏性变更如何发布（新增字段默认值、废弃周期、双版本并行期）。
  - 规模上界：分页/批量/超时上限，防止一次拉全量；接口目标 QPS 按 `quantification.md` 估。
  - 「不做什么」：本次不开放的接口能力，防止接口膨胀。
- **可裁剪**：成本分析、压测方案等与企业级无关章节。

## 数据模型设计

- **重心**：数据模型、存储设计、一致性。
- **必答项**：
  - ER 图（`erDiagram`，实体名英文驼峰、关系标注中文）+ 实体字段说明。
  - 索引设计与**查询匹配**：每个索引对应哪条查询、是否覆盖索引、写入放大的代价。
  - 读写比与访问模式假设（决定范式/反范式、宽表/多表）。
  - 一致性取舍：强一致/最终一致、事务边界、跨库一致性方案。
  - 分库分表只在该需求明确时展开，且必须给路由键、扩容方式、跨分片查询方案。
  - 存储量按 `quantification.md` 推（单条 → 增量 → 规划期总量）。
- **可裁剪**：消息与异步、可观测性等无关章节（轻量/标准档）。

## 性能与容量

- **重心**：基线、瓶颈、优化方案取舍与验证。
- **必答项**：
  - 现状基线与目标：QPS、RT（P99）、资源水位——按 `quantification.md` 给推导，不拍脑袋。
  - 瓶颈先给**假设与验证手段**（压测/采样/链路追踪/AB 对比），再给优化方案。
  - 每项优化写「预期收益 + 代价 + 回退开关」；缓存方案必须写失效策略与穿透/雪崩防护。
  - 容量规划：存储/带宽/连接的规划期总量 + 扩容触发阈值。
- **可裁剪**：与性能无关的企业级章节；轻量/标准档给验证步骤即可，完整档才展开压测方案。

## 安全

- **重心**：资产与信任边界、威胁与防护、审计与合规。
- **必答项**：
  - 资产清单与信任边界：谁可信、什么数据敏感、数据流向哪些外部系统。
  - 认证/授权模型：身份来源、权限粒度（RBAC/ABAC）、越权防护（水平/垂直越权分别给措施）。
  - 数据保护：传输与落库加密、密钥管理、脱敏；**日志与错误信息中不得出现明文凭据或敏感字段**。
  - 威胁—防护对照表：注入、重放、暴力破解、越权、敏感信息泄露等逐条给措施。
  - 审计与合规：留存什么、留多久、谁能查。
- **可裁剪**：性能压测、成本分析等无关章节。

## 迁移与重构

- **重心**：从现状到目标的**过程**，而不是目标形态本身。
- **必答项**：
  - 迁移步骤可分批、可中断、可回退：给出双写 / 影子流量 / 灰度切流的具体阶段与判据。
  - 数据迁移：一致性校验方法（对账口径、抽样比例）；回滚时的数据反向同步方案。
  - 兼容期：新旧接口/新旧表共存多久、谁先下线、下线判据是什么。
  - 回滚判据与触发条件：什么指标异常就回滚、回滚耗时多久、回滚后如何验证。
  - **不可逆动作清单**（删表、切主库、删旧代码）单独列出，写清执行前检查项与审批点。
- **可裁剪**：全新系统的方案可整体跳过本专题。

## 组合示例

| 需求 | 档位 | 专题 | 落点 |
|------|------|------|------|
| 给订单服务加本地缓存缓解 DB 压力 | 轻量 | 性能与容量 | 基线 + 缓存取舍 + 失效策略 + 验证步骤 |
| 设计一个 API 网关子系统 | 标准 | 架构设计 + API 设计 | 网关职责表 + 超时/重试策略 + 接口与鉴权 + 版本兼容 |
| 核心交易系统重构为微服务 | 完整 | 架构设计 + 迁移与重构 + 安全 | 完整档骨架 + 服务边界与数据所有权 + 双写切流与回滚 + 权限模型 |
| 订单库分库分表 | 标准 | 数据模型设计 + 迁移与重构 | 路由键与扩容 + 索引匹配 + 双写校验与回滚 |
