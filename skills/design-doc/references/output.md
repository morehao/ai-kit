# 落盘与收尾（output）

## 文件命名与存储

- 默认命名：`{主题关键字}-design-{YYYYMMDD}.md`
  - 示例：`用户认证-design-20260305.md`、`微服务迁移-design-20260305.md`、`订单系统分库-design-20260305.md`
- 存放位置：当前工作目录根目录；用户指定了目录则存到指定路径。
- 用户有明确命名/位置要求时以用户为准。

## 生成与收尾流程（严格执行顺序）

1. 用 `write` 生成**完整**方案文档，等待工具返回成功，确认落盘。
2. 文档含 Mermaid 图且本机能定位到本 skill 目录 → 跑图校验：
   ```bash
   node <本skill目录>/scripts/check-mermaid.mjs <生成文件>
   ```
   `[MERMAID-ERROR]` 必须修复重跑直至通过；校验不可用时（定位不到 skill 目录/依赖缺失）向用户说明原因。
3. 报告结果，格式：

   ```text
   ✅ 技术方案文档已生成: <文件路径>
   ```

4. 打开文件：**不自动执行 `code` 打开**。仅当满足全部条件才尝试：用户明确要求打开、当前宿主支持（本地 VSCode 等）、`code` 命令可用；执行失败或环境不支持时，提示用户手动打开路径，不阻塞收尾。

## 落盘后

- 不自动 `git add` / `git commit`；是否纳入版本管理由用户决定。
- 若用户接着要配图交付物（独立 SVG 架构图）或对该方案做源码级验证，分别提示 `svg-maker` / `project-insight` 的使用入口。
